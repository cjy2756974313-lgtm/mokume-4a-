## 1. 两类复现性问题必须分开记录

### R1：固定环境下的重复运行

代码版本、依赖、GPU、并发策略、线程数、全部随机源都相同，**背靠背**重跑同一配置。

**实测：在已检查的所有情形里，proc_params 逐位一致（最大绝对差 0.000e+00）。**

| 场景 | 时间 | 配置 | 结果 |
|---|---|---|---|
| 本地 Gate 0 | 10-27 13:xx | CN03 / res48 / 6 迭代，base vs p1(全关) vs p1(force_aux) | 87 属性，0.000e+00 |
| 服务器 res64/60 | 10-27 13:3x | B08 base 连跑 3 次（含/不含 `-contrast_diag`） | 74 张量，0.000e+00 |
| B2 前的等价性检查 | 10-27 15:59 | B08 b1 / res128 / 默认预算（与旧批比） | **1.967（不一致，见 R2）** |

结论：**R1 在本机/本服务器上不是问题**。逐位一致说明实现本身（含全部随机源）是确定的。

### R2：执行条件变化后的重复运行

任一项变化——并发数、同卡邻居负载、显存压力、线程调度、运行时刻——都算 R2。

**实测（B2 轮，B08，同批同代码同 seed；两次均为 `res128 / ITERS=0 / -stagec_fixed 0,0,0 / seed 1001`，同批 `JOBS=2`、`-gpu_mem_frac 0.12`、`-device cuda:2`。`base_s1001` 与另一 job 并行（808 s），`base2_s1001` 为末批、基本独占（307 s）。完整命令行见 `logs/b2_jobcmds.txt`）**

| 指标 | base | base2 | 相对差 |
|---|---:|---:|---:|
| 相位(detail) | 0.00621 | 0.00764 | **+23.0%** |
| 相位(nodetail) | 0.01565 | 0.01602 | +2.4% |
| 面 L1(detail) | 0.02842 | 0.02858 | +0.6% |
| 带间对比 \|ΔC\| | 0.00827 | 0.00527 | **−36.3%** |
| 调制深度 amp | 0.0236 | 0.0290 | **+22.9%** |
| 锚点 A_err | 0.00285 | 0.00311 | +9.1% |
| 外表面 F₁ | 0.0086 | 0.0073 | **−15.1%** |

另一处独立证据：同一命令在 10-26 与 10-27 两次运行，Stage A 最终损失 0.02287 vs 0.02307（+0.9%），经 Stage B/D 放大后 `proc_params` 差 1.967。

### 1.1 正确的表述

- **不能说**"算法本身有 20% 的随机性"——R1 **在 res48/6 与 res64/60 两档**已证伪这一点；**res128 + 默认预算档未做背靠背重复**，故对高预算档只能存疑。
- **可以说**"结果对计算执行条件敏感；在当前协议下，R2 量级的差异与多数被测效应同量级，因此小效应不可判"。
- 二者不能合并成一个"噪声值"上报。

## 2. 固定执行环境：必须记录与必须控制的项

### 2.1 必须记录（每个 job 一行，写进结果表）

| 项 | 取法 |
|---|---|
| 代码哈希 | `md5sum 4a_proc_p1.py COMMON/*.py` |
| 依赖版本 | `python -c "import torch,cv2,numpy;print(torch.__version__,cv2.__version__,numpy.__version__)"` |
| 设备 | `CUDA_VISIBLE_DEVICES` / `-device` 形参 + `CUDA_DEVICE_ORDER=PCI_BUS_ID` |
| 并发策略 | `JOBS`、`-gpu_mem_frac`、同卡其他进程（`nvidia-smi` 快照，前后各一次） |
| 线程 | `torch.get_num_threads()`、`OMP_NUM_THREADS`、`MKL_NUM_THREADS` |
| 随机源 | `random` / `numpy` / `torch` / **`cv2.setRNGSeed`** 全部固定；`cudnn.deterministic=True`、`benchmark=False` |
| 内存分配 | `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` |
| 墙钟 | 起止时间戳（现有 `timing_*.tsv` 已满足） |

### 2.2 必须控制

1. **基准与候选同波次**：同一配对的所有配置尽量在同一时间窗内启动；不要一个在空闲时段、另一个在满载时段。
2. **优先独占 GPU、顺序运行**建立基准；只在吞吐优先时才并行，且并行度写进结果。
3. **线程数显式固定**（建议 `OMP_NUM_THREADS=4`、`torch.set_num_threads(4)`），避免同一台机器上线程抢占不同。当前代码**未固定线程数**，这是 R2 的一个已知来源。
4. 记录 `nvidia-smi` 快照（现有 `env_start_*.txt` / `env_end_*.txt` 已满足）。

> 现状评估：§2.1 的记录项基本齐备（哈希、种子、并发、墙钟、GPU 快照都有）；**缺的是线程固定**与"同波次启动"的纪律。

## 3. Stage C 的处理方式（本轮最硬的教训）

### 3.1 已观察到的现象

B 轮 12 个 job（同批、同 seed、Stage C 均为默认 27 格搜索）的 argmin：

| 样本 | base | c7 | b1 |
|---|---|---|---|
| B08 | (−1,−1) | (−1,−1) | **(0,0)** |
| KR07 | (−1,−1) | (−1,−1) | **(0,−1)** |
| K04 | (0,0) | (0,0) | (0,0) |
| NR04 | (0,0) | (0,−1) | **(−1,−1)** |

记法 = (pore, ray)，fiber 恒 0。**4 个样本里 3 个、同一批内、同一 loss 家族的三个配置选了不同格点。**

`grid_search_sizes` 用 27 个候选的风格损失取 argmin，候选之间评分差常在小数第三位；R2 级扰动即可翻转选择。而 `pore_occurance_ratio` 从 0 变到 −1 意味着"管孔是否出现"的整体切换——这是比任何配色微调都大的视觉变化。

### 3.2 规则

| 实验类型 | Stage C 处理 | 理由 |
|---|---|---|
| **损失消融 / 相位监督形式配对测试**（B1、B2 这类） | **固定并记录**同一声明的格点（`-stagec_fixed "0,0,0"`，跳过 27 格搜索）；三配置共用 | 让差异只反映目标损失变化 |
| 研究 Stage C 本身（网格设计、语义化、评分函数） | 作为**独立实验**，不与相位损失混跑 | 否则无法归因 |
| 正式候选 / 38 块评价 | 沿用生产口径（27 格），并**逐样本记录选中的格点** | 生产协议不可改；记录是为了事后可解释 |

配套要求：
- 每张结果表都必须带"Stage C 格点"一列；
- 若同一配对内格点不一致，该样本的差异**不得**归因于被测损失。

> 现有代码已支持 `-stagec_fixed "f,p,r"`（默认空 = 原 27 格行为，Gate 0 复验 0.000e+00）。

## 4. 重复次数与报告口径

### 4.1 最小复现性检查

**原始 1 次 + 重复 2 次 = 3 次独立运行**（同配置、同 seed、同波次窗口内），逐次记录：

| 运行 | phase(det) | L1 | amp | \|ΔC\| | F₁ | 备注（并发/耗时） |
|---|---|---|---|---|---|---|
| run1 | | | | | | |
| run2 | | | | | | |
| run3 | | | | | | |
| **中位数** | | | | | | |
| **极差（max−min）** | | | | | | |

- 对**阈值化指标**（F₁、Ring F1）若极差超过被测效应的 1/2，追加重复；
- 报告一律给**逐次原始值 + 极差**，不要只给均值。

### 4.2 判读规则（与预登记配合）

> 只有当"候选 vs 基准"的差异**大于同配置重复运行的极差**时，才允许称其为效应。

若效应落在极差之内：结论写"不可判定"，不写"改善/退化"。

- **该规则的前置条件在本项目尚未满足**：极差本身应由 ≥3 次运行估计，而目前只有 1 对运行（B08）。因此 §4.2 至今**未被真正执行过一次**，只能作为今后要求。

### 4.3 不许做的事

- **不要**用 3 次运行去估计标准差、置信区间或"噪声分布"——n=3 不足以支撑统计推断；
- **不要**把 R1（应为 0）与 R2（环境敏感）合并成一个数字；
- **不要**在已经知道结果后再挑选重复次数或指标口径。

## 5. 正式评价的边界（不变）

1. **斜切面只在候选冻结后**用于正式评价；绝不参与损失设计、参数选择、网格搜索或颜色提示。
2. **DISTS 属正式评价指标**，只能在候选冻结后的 38 块流程里报。B2 属机制测试，**本轮不计算 DISTS 是正确的**，不应为"补齐指标"而突破协议。
3. 机制测试的结论只能写"机制是否成立/是否可判"，不能写"质量提升"。
4. 生产 v2 目录只读；晋升流程独立于本协议。

## 6. 受影响结论的分级表述（按指标分别定性）

原数字一律保留，不删除、不整段作废；但每条都要标清**证据类型**。三级：

- **A 级（可用）**：批内实测，效应量远大于观察到的极差，或有跨配置/跨 seed 重复。
- **B 级（方向性）**：批内实测变化真实存在，但量级与执行条件敏感性同阶；**不得推广为跨环境稳定效应**。
- **C 级（不可判定）**：预登记判据未通过（含判据 0 噪声底），或效应落在极差之内。

| 结果 | 原数字 | 分级 | 应当采用的结论 |
|---|---|---|---|
| B1 带间对比误差下降 | −88.5%（4/4 同向） | **A** | 保留为**强烈的批内目标拟合结果**；四样本均同向，但**不能**据此宣称整体反演质量改善。 |
| B1 外表面 F₁ 下降 | −19.7% | **B** | 保留为**本批次实测退化**；已发现执行条件敏感性，**不把该效应量直接推广为跨环境稳定效应**。 |
| B2 锚点误差改善 | 0.00510→0.00400（−22%） | **B** | 记录为**目标拟合部分成立**；逐样本判据未通过（K04 +40%），且存在参数漂移（K04 `late_wood_start` +1102%），**不能认定锚点约束有效解决了形状问题**。 |
| B2 相位 / 调制深度 / F₁ | +13% / NR04 0.82× / 0.0433 | **C** | **按本轮预登记规则判定不通过**；其中受环境变化影响的效应量，**注明稳定性尚未验证**。 |
| B2 KR07 锚点误差 | −71% | **A**（单样本） | 可写"在该样本上锚点目标被显著改善"；仅单样本、单次运行，**不外推**。 |
| c7 detail 相位恶化 | +17.7%（Gate 2A） | **B** | 保留 Gate 2A 的**实测结果**，但标注为**该实验设置下的观察**；跨执行环境的效应稳定性**尚未核实**。 |
| c7 nodetail 相位改善 | −19.6%（7/8 改善） | **B** | 同上；7/8 同向提高了可信度，但仍未测极差。 |
| R3-1（res64/60，8 样本 × 2 seed） | −19.6% 等 | **B** | 双 seed 已部分压噪，但**未做复现性检查**，应补标该限制。 |
| 死参数 / 梯度量级 / 初始 C≡0 / Stage C 格点表 | 工程事实 | **A** | 不依赖重复运行，属代码与日志事实，可直接引用。 |

### 6.1 两条不能混的算术

1. **B1 的对比度改善（−88.5%）与环境变化下的对比度变化（−36%）是同类指标，但比较范围不同**：前者是"候选 vs 同批 base"的批内配对差，后者是"同一配置两个时点"的极差。**两者不能相减来估算"净效应"**，也不能相加成"总不确定性"。
2. **单次环境变化不等于噪声分布**：它只是"观察到的极差"的一个样本点（n=1 对运行）。任何需要分布假设的推断（标准差、置信区间、显著性检验）在本轮数据上都**不成立**。

### 6.2 "方向性"与"不可判定"的分界

- **能说"发生了变化"**：批内配对差（同批、同 seed、同 Stage C 格点）且方向跨配置/跨样本一致 → B 级。
- **不能说"变化能否复现"**：跨执行条件、跨时间、跨批次的稳定性 → 本协议下**未验证**。
- **不能说"改善了正式指标"**：只有通过 38 块正式评价（含斜切面 DISTS）才成立，本轮**无一条**。

## 7. 复现一份可比结果的推荐步骤

```bash
# 1) 固定环境（独占、顺序、固定线程）
export OMP_NUM_THREADS=4 MKL_NUM_THREADS=4
export CUDA_DEVICE_ORDER=PCI_BUS_ID TORCH_HOME=/home/gast/.cache/torch
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
nvidia-smi --query-gpu=index,memory.used,utilization.gpu --format=csv > env_before.txt

# 2) 固定 Stage C（损失消融场景）
STAGEC="-stagec_fixed 0,0,0"

# 3) 三配置 × 三次，顺序执行，记录墙钟
for run in 1 2 3; do
  for cfg in base b1 b2; do
    python 4a_proc_p1.py -id B08 -res 128 -iters 0 -skip_volume 1 \
      -seed 1001 -tag ${cfg}_r${run} $STAGEC ...
  done
done

# 4) 报告极差，而不是均值
```

检查清单（每条都要能答"是"）：
- [ ] 代码/依赖哈希已记录
- [ ] 四个随机源（random/numpy/torch/**cv2**）已固定
- [ ] 线程数已显式设定并记录
- [ ] 配对配置在同一时间窗内启动
- [ ] Stage C 已固定或已逐样本记录
- [ ] 至少 3 次重复，报告了极差
- [ ] 效应 > 极差才称"效应"
- [ ] 未使用斜切面/DISTS 参与机制测试

## 8. 本协议的适用限度

- 本文的 R2 极差来自**一个样本（B08）、一对运行**，是**观察到的范围**，不是分布的估计；不同样本/指标的敏感度可能不同。
- §6 的降级表按"同量级即降级"的保守口径执行；若将来用 3 次重复测出更小的极差，可据此上调。
- 协议本身不改变官方评价；它只约束**机制测试**如何报告。
